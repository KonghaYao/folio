# 服务端存储、权限与多设备同步

## 部署边界

Bun 运行 Hono HTTP 服务，SQLite 同时保存画板、对象、文件字节、设备映射和授权关系。默认数据库路径为 `./data/folio.sqlite`。生产实例用 `FOLIO_DB` 指向持久磁盘，将该目录作为卷挂载。SQLite 使用 WAL、`synchronous=FULL`、外键和 5 秒 busy timeout。建议每个数据库使用一个 Bun 服务进程，并让反向代理保留 SSE 流。多进程共享同一台机器的数据库时，另一进程的事件通过 12 秒心跳补查。此版本没有跨节点数据库复制。

TLS 终止在反向代理时，设置 `PUBLIC_ORIGIN=https://实际域名`。服务会据此检查浏览器写入的 Origin 并签发 Secure cookie。匿名浏览器首次访问 API 时获得独立工作区。创建工作区和上传占用部署者磁盘，面向受限团队部署时可在代理配置团队登录与全站存储配额。

## 数据模型

| 数据 | 保存位置与语义 |
| --- | --- |
| 画板 | `boards` 保存标题、单调递增的文档版本、最后更新时间、对象及附件字节计数 |
| 对象 | `items` 以画板 ID 和对象 ID 为主键。存储完整 Quickdraw 记录或场景记录。对象最后修改版本与删除标记用于差量同步 |
| 笔迹 | 绘制对象保留 Quickdraw 点列，以及 Folio 笔刷、宽度、颜色、采样位置、压力、双轴倾角、扭转和切向压力 |
| 写入回执 | `receipts` 保存每个画板、工作区身份、操作 ID 的请求摘要与提交版本。断线重试可以取回原回执 |
| Chat | `chat_turns` 以画板、工作区身份与回合 ID 隔离完整的问答，不保存模型密钥。配对设备能读取已完成的对话 |
| 文件 | `assets` 保存 MIME、名称、长度、不可变的字节。授权从所属画板继承。音视频可按 HTTP Range 读取所需的字节段 |
| 跨画板复制 | `adopted_assets` 记录特定来源附件在目标画板的独立副本，重复复制同一资源复用目标文件。服务先验证来源可读、目标可写，然后在同一事务内复制字节。来源画板后续删除不影响目标副本 |
| 设备 | HttpOnly 的随机 `folio_session` 对应设备，服务只保存摘要。一个设备可保留多个工作区，切换时仅更新该设备的活动工作区。显示给浏览器的工作区 ID 只对该设备有效 |
| 权限 | `members` 保存当前角色，`invitations` 保存链接密钥摘要，`sharing_grants` 关联实际兑领过的链接。所有者撤销链接后重新计算剩余角色 |
| 组织 | 文件夹、收藏、移动与回收站按工作区身份保存。同一工作区配对设备共享这套组织信息，各自拥有独立入口的协作者可分别整理共享画板 |

## 加入画板与配对设备

分享链接给浏览器授予一张画板的查看或编辑权限。所有者可撤销链接和经它取得的授权。用户通过多个链接加入时，保留剩余链接能授予的最高角色。撤销最后一条授权后，服务拒绝对象、差量、文件和新的事件请求。

自己的平板加入整个工作区时，先在电脑选择“同步我的设备”，再在平板打开配对链接。令牌用 32 个随机字节生成，5 分钟后失效，成功兑领和添加设备映射在同一事务中完成。已有画板的平板会保留原工作区，可以切回。配对没有复制 HttpOnly cookie。设备的本地缓存依据随活动工作区变化的 `folio_cache` 标识隔离，服务不会将该标识当作访问凭证。

配对设备拥有工作区完整权限，应向自己的设备传递链接。“同步我的设备”会列出当前工作区的浏览器、平台与最近活动时间。从另一台已配对设备可以移除原设备。服务立即关闭该设备当前进程上的事件流，撤销未兑领的配对码。被移除的设备回到自己的其他工作区；仅有一个工作区时取得新空工作区。服务无法回收已经离线复制或导出的字节，离线设备下次联网后才会发现权限变化。清除唯一设备的 cookie 后，可通过尚有访问权的已配对设备重新配对。数据库备份保留设备映射，保留浏览器 cookie 的同源设备可继续访问恢复的实例。恢复到新域名时，浏览器需要该域名的访问凭据。

## 编辑、断线与冲突

1. 首次进入画板读取 `GET /api/boards/:id`。返回的 `rev` 与全部对象源自同一 SQLite 读事务。
2. 客户端按批提交 `POST /api/boards/:id/ops`。每批携带唯一的 `opId`、所见版本 `baseRev`、待保存对象和待删除 ID。服务在立即写事务中验证权限、对象结构及碰撞，提交对象、墓碑、画板版本与回执后才返回成功。
3. 客户端可能基于较早的版本提交。所有改动对象都未在此后更新时自动提交。若其中一个对象已被修改或删除，则整批回滚并返回 HTTP 409。相同操作 ID 和原内容可安全重试。变更后的内容需要新的操作 ID。
4. 服务通过 SSE 广播新版本。订阅建立时先发送当前版本，可补上先读后订阅之间的编辑。接收方通过 `GET /api/boards/:id/changes?since=N` 只取变动对象的最终状态以及删除记录；同一读事务返回标题和版本。超过当前版本的游标返回 409，由客户端重取完整画板。
5. 客户端用服务端最终状态重放尚未确认的本地编辑，对能独立合并的属性分别保留。遇到无法合并的形状编辑时，保留服务端记录，并尽可能把本地编辑写为副本且通知用户。历史撤销不会跨过对方已覆盖的编辑。
6. 对某画板授权发生变化时，服务立即发布事件。最终丧失权限的订阅会关闭。所有后续读写以当时的权限重新检查。

## 在线协作者与跟随视图

光标与视口以画板坐标发送，保存在当前 Bun 进程内存。服务每 100 毫秒至多合并广播一次，通过同一条 SSE 的 `presence` 事件发送；画板版本保持不变。每个标签页取得独立的短期公开标识，相同工作区的不同设备也会单独出现。客户端定期刷新活动状态，服务在 25 秒无心跳后清理标签页，画板在线列表最多容纳 64 个标签页。关闭页面时会提前发送离开消息。

在画板左下“协作者”中选择“跟随视图”，浏览器将对方的世界坐标范围适配到自己的屏幕。主动移动或缩放自己的画布会退出跟随。跨进程部署时在线参与者仅包含本进程用户，单实例或按画板将连接路由至同一个进程可保持完整的在线列表。

## 在线备份与恢复演练

从项目目录执行。下方命令使用三个不同的数据库文件。输出路径须是新路径，命令会拒绝覆盖已有文件。

```sh
bun server/backup.ts backup ./data/folio.sqlite ./backups/folio-2026-11-25.sqlite
bun server/backup.ts restore ./backups/folio-2026-11-25.sqlite ./restore/folio.sqlite
FOLIO_DB=./restore/folio.sqlite HOST=127.0.0.1 PORT=3010 bun server/index.ts
```

1. 备份期间源服务可继续写入。SQLite `VACUUM INTO` 创建一个包含已提交 WAL 内容的一致快照。服务检查 SQLite 完整性与外键，刷新文件与目录，在同一文件系统原子发布目标文件。输出文件权限为 0600。
2. 在恢复实例访问 `/api/health`。用原浏览器的同源测试环境或运维测试身份读取画板、附件与分享权限，并提交一次测试编辑。将恢复副本用于演练，避免改变备份文件。
3. 确认切换时，先停写并停止原服务，设置 `FOLIO_DB` 指向已验证的恢复路径，再启动服务。数据库备份后的新编辑只在原数据库中，应依据实际恢复点决定何时切换。强制中止后直接启动原数据库时，SQLite 会应用已提交的 WAL。运行中直接复制单个主数据库文件可能缺少 WAL 页面。
4. 备份同时包含私有画板和附件，应保存在受到访问控制的目录。客户端 JSON 副本只服务单画板移植，没有设备映射、组织信息或成员权限。

`bun test server/restart.test.ts` 会启动真实 Bun 进程，用 HTTP 写入并取得回执，在线备份，发送 SIGKILL，再分别启动原库与恢复库进行验证。`bun test server/app.test.ts` 覆盖笔采样回读、权限、重试、冲突回滚、差量、设备配对和文件字节恢复。

## 限额与保留

| 项目 | 当前限制 |
| --- | --- |
| 单次写入 | JSON 请求最多 4 MiB，最多 4,096 个对象改动 |
| 活跃画板内容 | 每画板 32 MiB，按非空对象 JSON 的 UTF-8 字节累计 |
| 单个文件 | 原始上传最多 24 MiB |
| 附件总量 | 每画板 256 MiB，含已上传但暂时没有形状引用的文件 |
| 配对 | 令牌 5 分钟有效，已使用令牌立即删除 |
| 事件 | 单进程即时通知，12 秒心跳；落后过多的订阅关闭，由浏览器重连并读取差量 |

删除画布上的形状会留下墓碑。写入回执、附件和墓碑随画板保留，以支持旧设备回连、撤销与重复请求。删除最后一个附件形状也会保留原始文件，所以继续向长期编辑的画板上传内容可能触及附件限额。相同来源经跨板复制会复用目标文件；普通重复上传各占一份。画板的个人回收站保留整个文档。所有者永久删除画板后，外键级联清理其附件、对象、回执和授权。

32 MiB / 256 MiB 是逻辑内容限额，SQLite 索引、墓碑、回执、历史文件与 WAL 另占磁盘。当前没有依据时间删除墓碑或回执的后台清理任务。运维时监测整个数据库目录和备份卷可用空间，定期复核大画板并演练恢复。对于长期积累大量无引用附件的画板，可导出可编辑副本后导入为新画板，核对附件并重新授予分享权限，再由所有者决定旧画板的保留期。
